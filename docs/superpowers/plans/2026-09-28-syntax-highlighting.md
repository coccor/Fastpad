# Syntax Highlighting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rich, theme-aware syntax highlighting for JSON, Markdown, XML/SVG and 19 more languages via
the already-shipped `Lexilla.dll`, driven by one language registry.

**Architecture:** `SyntaxColors` grows into a semantic role palette (one per theme). Each Lexilla
lexer family gets a `const fn` style map from its `SCE_*` styles to roles, built per theme at compile
time. A `LANGUAGES` registry row per language carries its display name, extensions, file names,
Lexilla lexer name, keyword sets and lexer properties. Detection, `LanguageManager::apply`, the status
bar, the default save extension, the View → Language submenu and the palette all read it.

**Tech Stack:** Rust 2024, `windows-sys`, Scintilla 5.6.6 + Lexilla 5.5.3 (direct-function calls).

**Spec:** `docs/superpowers/specs/2026-09-28-syntax-highlighting-design.md`

## Global Constraints

- No native/DLL changes: every lexer used is already in `native/out/x64/Lexilla.dll`.
- Lexilla stays lazily loaded; a plain-text session never loads it.
- Style tables are compile-time `static`s built with `per_theme_styles!`.
- Light/Dark `text`, `background`, `string`, `number`, `heading`, `code`, `code_background` values
  are unchanged; Catppuccin keeps `text`, `base`, `green`, `peach`, `red`, `blue`, `mantle` roles.
- `src/editor/scintilla_constants.rs` is regenerated by `tools/generate-scintilla-constants.ps1`,
  never hand-edited.
- No backward-compatibility code (language is not persisted).
- A new `windows` crate feature would need `tools/audit-dependencies.ps1` updated; none is expected
  (`CheckMenuItem`, `MF_CHECKED`, `MF_UNCHECKED` are in `Win32_UI_WindowsAndMessaging`, already on).
- Testing discipline (project preference): compile gate is
  `cargo clippy --all-targets --all-features -- -D warnings`; per part run only the named targeted
  tests; the full serial suite runs once, in Part 9. Window tests need `-- --test-threads=1`.

## Review Focus

1. Upper-case extensions and dotfiles (`.ENV`, `.env.local`, `Cargo.lock`, `.bashrc`) must detect
   the right language — pinned in Part 3's detection test.
2. Switching theme while an XML/HTML tab is active must repaint tags in the new theme's colours —
   pinned in Part 5's `reapplying_with_another_theme_restyles_xml_tags` test.
3. The user's font face and size must reach lexer styles above 39 (HTML's `SCE_HJ_*` are 40–53) —
   pinned in Part 1's `view_settings_reach_every_style_number` test.
4. On an image tab every language command is greyed like the other text commands — pinned in
   Part 6's `every_language_command_needs_text` test.
5. New-note / Save-As default extension for the new languages (YAML → `yaml`, Plain Text → `md`) —
   pinned in Part 3's `default_extension_comes_from_the_registry` test.

```rust
/// One Scintilla lexer style's look: `style` is the lexer-specific `SCE_*` style number.
#[derive(Clone, Copy, Debug)]
pub(crate) struct LexerStyle {
    pub(crate) style: u32,
    pub(crate) foreground: u32,
    pub(crate) background: u32,
    pub(crate) bold: bool,
    pub(crate) italic: bool,
}

impl LexerStyle {
    pub(crate) const fn bold(mut self) -> Self {
        self.bold = true;
        self
    }

    pub(crate) const fn italic(mut self) -> Self {
        self.italic = true;
        self
    }
}

/// What a token is, independent of language; each theme gives every role a colour.

impl SyntaxColors {
    pub(crate) const fn role(&self, role: Role) -> u32 {
        match role {
            Role::Text => self.text,
            Role::Comment => self.comment,
            Role::Keyword => self.keyword,
            Role::String => self.string,
            Role::Number => self.number,
            Role::Operator => self.operator,
            Role::Key => self.key,
            Role::Tag => self.tag,
            Role::Attribute => self.attribute,
            Role::Type => self.type_name,
            Role::Function => self.function,
            Role::Preprocessor => self.preprocessor,
            Role::Variable => self.variable,
            Role::Escape => self.escape,
            Role::Heading => self.heading,
            Role::Emphasis => self.emphasis,
            Role::Link => self.link,
            Role::Error => self.error,
        }
    }
}

/// Style `id` in `role`'s colour on the theme background; comments are italic.
pub(crate) const fn style(colors: &SyntaxColors, id: u32, role: Role) -> LexerStyle {
    LexerStyle {
        style: id,
        foreground: colors.role(role),
        background: colors.background,
        bold: false,
        italic: matches!(role, Role::Comment),
    }
}

/// Style `id` as code: the code colour on the code background.
pub(crate) const fn code(colors: &SyntaxColors, id: u32) -> LexerStyle {
    LexerStyle {
        style: id,
        foreground: colors.code,
        background: colors.code_background,
        bold: false,
        italic: false,
    }
}
```

```rust
/// Detects a file's language from its whole file name, then its extension, case-insensitively.
/// Never touches disk or Win32.
pub fn detect_language(path: &Path) -> Language {
    let Some(name) = path
        .file_name()
        .and_then(|name| name.to_str())
        .map(str::to_ascii_lowercase)
    else {
        return Language::PlainText;
    };
    let by_name = LANGUAGES.iter().find(|row| {
        row.file_names.iter().any(|pattern| match pattern.strip_suffix('*') {
            Some(prefix) => name.starts_with(prefix),
            None => name == *pattern,
        })
    });
    if let Some(row) = by_name {
        return row.language;
    }
    let extension = Path::new(&name)
        .extension()
        .and_then(|extension| extension.to_str())
        .unwrap_or_default();
    LANGUAGES
        .iter()
        .find(|row| row.extensions.contains(&extension))
        .map_or(Language::PlainText, |row| row.language)
}

pub fn display_name(language: Language) -> &'static str {
    spec(language).name
}

/// The extension a new file in `language` is saved with; plain text notes are Markdown files.
pub fn default_extension(language: Language) -> &'static str {
    spec(language).extensions.first().copied().unwrap_or("md")
}
```

```rust
    /// Applies `language`'s lexer, lexer options, keyword sets and `theme`'s style table to
    /// `editor`. A language without a lexer installs Scintilla's null lexer and never touches
    /// Lexilla. `Lexilla.dll` loads on the first lexed language. On a Lexilla load or
    /// lexer-creation failure the editor is left exactly as it was and the error is returned.
    pub fn apply(&mut self, editor: &Editor, language: Language, theme: Theme) -> Result<()> {
        let spec = registry::spec(language);
        let Some(name) = spec.lexer else {
            editor.set_lexer(0)?;
            return Ok(());
        };
        let lexer = self.ensure_lexilla()?.create_lexer(name)?;
        editor.set_lexer(lexer)?;
        for (key, value) in spec.properties {
            editor.set_lexer_property(key, value)?;
        }
        for (set, words) in spec.keywords.iter().enumerate() {
            editor.set_keywords(set, words)?;
        }
        editor.clear_all_styles()?;
        for style in (spec.styles)(theme) {
            editor.set_style(
                style.style,
                style.foreground,
                style.background,
                style.bold,
                style.italic,
                DEFAULT_FONT_FACE,
            )?;
        }
        Ok(())
    }
```
